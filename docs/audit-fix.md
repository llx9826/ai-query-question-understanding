# 审计持久化修复与验收

2026-09-15 · Plan v1.13

本批审计修复已完成，六个业务模块及模型配置保持原样。真实复测6题均符合预期，14次模型调用、118条阶段记录完整落库，写入异常0次。仍使用同一个SQLite文件，没有Redis，没有新增模型调用或自动重跑业务。

## 根因已复现

审计原来在事件循环中同步写SQLite，会话则由AgentScope的异步SQLAlchemy连接写同一个文件。会话持有写锁时，同步审计会阻塞事件循环，使异步事务无法及时继续提交，最终报SQLITE_BUSY。WAL允许读写并行，并不允许多个写者同时写入。[SQLite官方说明](https://www.sqlite.org/wal.html)

另外存在两个独立问题：

- Trace.write一旦失败就跳过后续阶段，导致一处错误扩大成整条链路日志缺失。
- 请求结束写失败后，数据库保留的是running、finished_at为空、logging_failed=0。此前只看失败标志和已有阶段，容易误判完整。上批H01正是这个状态，并不是一次错误被成功“清零”。

受控复现使用真实SQLite和异步事务，没有调用模型：

| 相同条件 | 修复前 | 修复后 |
|---|---|---|
| 事务释放安排 | 20毫秒后 | 20毫秒后 |
| 完成/阻塞耗时 | 205毫秒，超时 | 41毫秒，完整完成 |
| SQLite错误 | SQLITE_BUSY，错误码5 | 无 |
| 保存阶段 | 0/2 | 2/2 |
| 请求结束记录 | 缺失，仍为running | 已结束 |

这是锁竞争的受控复现，不是整个问数接口的速度对比。

## 改动边界与处理方式

只修改5个应用文件：

| 文件 | 变化 |
|---|---|
| app/infrastructure/query_audit/store.py | 在线审计使用标准ThreadPoolExecutor单写线程；SQLAlchemy短事务；幂等写入；新增写失败诊断表；检查完整性 |
| app/contracts/tracing.py | 一次失败后继续记录；结束事件带完整开始快照和预期阶段数；异步请求收尾等待落库；日志故障不覆盖业务异常或取消 |
| app/bootstrap.py | 装配线程写入适配器，正常退出时等待已提交审计写完 |
| app/orchestration/query_workflow.py | 改用异步审计收尾上下文，业务DAG不变 |
| app/web/routes.py | 进度返回audit_status/audit_complete及应写/已写阶段数；本轮记录缺失时不借用上一轮成功记录 |

没有修改app/modules下的任何业务实现，没有更改Excel数据、问题理解、SQL生成、实体绑定、解释策略或模型型号。另增测试、复现脚本、评测器和文档。

写入过程复用Python标准线程池与SQLAlchemy，没有自建线程调度系统或消息中间件。阻塞IO移到线程执行，是Python官方对异步程序的处理方式。[Python异步IO说明](https://docs.python.org/3/library/asyncio-dev.html#running-blocking-code)

开始和结束事件仍分别入库，支持过程中查看进度。结束事件携带完整输入快照，开始写入失败后，结束时可以补齐该记录；事件使用稳定trace_id/stage_id幂等写入。历史错误标记采用只增不清的逻辑，不会被后面的成功写入覆盖。没有重试模型、重新执行SQL或重新跑业务节点。

诊断表query_trace_write_failures记录trace_id、stage_id、所属模块/阶段、写入操作、异常类型、SQLite错误码/名称和发生时间，不记录可能含凭证的异常正文或SQL参数。诊断本身暂时无法写入时，保留到后续成功的审计事务写入；同时输出安全的运行日志。

完成判定同时要求：请求有finished_at、没有写入失败标记、实际阶段数等于预期阶段数、全部阶段已结束。API区分complete、pending、failed、incomplete，不能把队列提交成功或旧的running记录当作落库完成。

## 使用与边界

不增加配置，原docker compose和AIQ_SQLITE_PATH继续使用。启动时由metadata.create_all补建诊断表，既有会话和审计表不删除、不清空。没有将上批缺失的历史日志伪造补齐，原失败记录保留。

正常运行与正常退出会等待审计写入；强杀或机器掉电前尚未提交的队列内容不能承诺必达。缺少根记录、结束标记或阶段时会判定为未完整；业务恢复继续使用AgentScope已保存检查点。数据库持续不可写时也不能保证日志落盘，此时保留安全错误日志，不能声称审计完成。本轮没有引入额外持久化队列。

复现和证据位于validation-audit/，包括修复前源文件快照、前后复现JSON、全量与定向测试、真实6题manifest/results/audit/scores、人工复核和变更清单。真实模型测试运行命令：
